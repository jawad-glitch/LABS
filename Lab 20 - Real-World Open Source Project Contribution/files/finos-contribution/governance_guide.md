# FINOS Perspective Governance Study Guide

## Documents to review
- [ ] Repository CONTRIBUTING.md
- [ ] Repository DEVELOPMENT.md
- [ ] Code of Conduct
- [ ] Security policy
- [ ] License and NOTICE files
- [ ] Applicable FINOS contributor agreement requirements

## Contribution workflow
- [ ] Search for an existing issue before proposing work
- [ ] Discuss substantial changes before implementation
- [ ] Fork the repository and use a focused feature branch
- [ ] Follow the repository's documented tests and coding standards
- [ ] Submit a clear pull request
- [ ] Respond to review comments and update the branch

## FINOS governance and compliance
- Review whether an ICLA or applicable CCLA is required.
- Follow any DCO sign-off requirement stated by the repository.
- Do not assume that opening a PR means legal or governance checks are complete.
- Maintainers determine acceptance and merging.

## Community participation
- Be respectful and constructive.
- Ask for clarification when review feedback is unclear.
- Explain technical trade-offs with evidence.
- Do not claim an issue is resolved unless the change addresses its acceptance criteria.
