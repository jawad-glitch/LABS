# Newcomer's Guide to FINOS Legend

## Welcome

This guide introduces a practical workflow for people who want to contribute to FINOS Legend.

## Before contributing

- Install Git and the tools required by the area you intend to change.
- Read the repository contribution guidelines and code of conduct.
- Explore the project documentation and existing issues.
- Look for a small, clearly scoped improvement before attempting a large change.

## A typical contribution workflow

1. Fork the repository on GitHub.
2. Clone your fork and add the original repository as `upstream`.
3. Create a focused feature branch.
4. Make a small change that addresses a clear need.
5. Run the relevant checks and review the complete diff.
6. Commit with a descriptive message.
7. Push the branch and open a pull request against the appropriate upstream branch.
8. Respond constructively to review feedback and update the pull request.

## Good contribution practices

- Follow existing project conventions rather than introducing unrelated formatting changes.
- Keep each pull request focused and explain why the change is useful.
- Add or update tests when changing code.
- Keep documentation accurate and links relevant.
- Never include credentials, tokens, private keys, or confidential data in commits.

## Getting help

Search existing issues and discussions before opening a new question. When asking for help, include the relevant context, steps already tried, and any useful error output.

## Coding standards and review expectations

- Match the conventions and architecture already used in the project.
- Prefer small, readable changes with clear names.
- Add tests for behavior changes and run relevant existing checks.
- Update documentation when behavior or setup instructions change.
- Explain design decisions and respond respectfully to reviewer suggestions.
